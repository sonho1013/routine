You are given a list of similar or closely related facts about the user, plus
the structured driving context shared by all of those facts.
These facts are assumed to be repetitive and could be considered as a habit.

Your goal is to reword all these facts into a SINGLE habit description that
EXPLICITLY incorporates the relevant context (when, where, what state of the
car), so the habit is unambiguous about the situation in which it applies.

# CONTEXT GUIDANCE

Use the structured context fields below to anchor the habit description in:
- time of day (time_bucket / hour)
- workday vs weekend (weekday)
- location (geofence and poi_type — these distinguish e.g. "office gate
  parking lot" from "shopping mall parking lot" even though both are
  parking_garage)
- vehicle state (parked / engine_started / driving / crawling)
- weather/comfort state (wiper_state, temp_bucket)
- security/access state (door_lock, approach_unlock, window_state)

If a context field is "unknown" or null, ignore it — do NOT mention it.
If a context field IS set, weave it naturally into the habit text.

GOOD habit names mention the WHEN and WHERE concretely:
  ✓ "rolls down driver window when arriving at the office gate parking lot"
  ✓ "switches to silent drive mode on the evening commute home"
  ✓ "engages climate to 23°C while parked at home in the morning"

BAD habit names are generic and lose the situation:
  ✗ "Always Roll Down Driver Window"           (no place, no time)
  ✗ "Silent Secure Drive Mode"                 (no time of day, no destination)
  ✗ "Climate Control Adjustment"               (no when, no where)

Use ONLY stated information, no assumptions.
Output a habit text and a confidence score from 0.0 (not confident at all) to
1.0 (really sure).
If you are not confident at all, cannot make a decision or think there is no
real habit in the list of facts, output "NO_HABIT",0.0.
Otherwise output <habit_text>,<confidence_score>

# OUTPUT FORMAT (1 line CSV):
habit_text,confidence_score
